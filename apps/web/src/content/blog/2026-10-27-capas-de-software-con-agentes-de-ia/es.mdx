Un agente de IA que funciona en una demostración no es lo mismo que uno que se puede dejar trabajando. La diferencia no está en el modelo, sino en lo que lo rodea: qué pasa cuando falla, cuánto cuesta cada ejecución y cómo sé que seguirá acertando dentro de un mes.

Este es el mapa de capas que yo pondría alrededor de una automatización o de un agente. No hace falta todo desde el primer día: al final explico por dónde empezaría.

## Un agente es software con una pieza que no es predecible

Una automatización clásica hace siempre lo mismo con los mismos datos. Un agente usa un modelo que puede responder distinto ante la misma entrada. Por eso, además de comprobar que no se cae, hay que comprobar que **decide bien**. Casi todas las capas tienen esas dos partes: la que vale para cualquier software y la que existe porque hay un modelo de por medio.

## 1. Arquitectura: el modelo propone, el código decide

El modelo lee un correo y dice «esto parece un pedido de tres artículos». Crear el pedido, tocar la base de datos o enviar un mensaje lo hace código normal, con reglas claras.

```ts title="validar-salida.ts"
import { z } from 'zod';

// El modelo devuelve texto; antes de usarlo, se valida contra un esquema.
const Pedido = z.object({
  clienteId: z.string(),
  lineas: z.array(z.object({ articuloId: z.string(), cantidad: z.number().int().positive() })).min(1),
  confianza: z.number().min(0).max(1),
});

export function leerPedido(salidaDelModelo: unknown) {
  const resultado = Pedido.safeParse(salidaDelModelo);
  if (!resultado.success) return { estado: 'revisar', motivo: 'salida no válida' } as const;
  return { estado: 'ok', pedido: resultado.data } as const;
}
```

Y una parte de los casos, incluso los que salieron bien, los revisa una persona de vez en cuando: es la forma de ver errores que ninguna métrica detecta. Si la proporción de casos corregidos sube, el agente está empeorando antes de que nadie se queje.

:::note
Las trazas pueden contener datos personales (el texto de un correo, un nombre). Hay que decidir qué se guarda, cuánto tiempo y quién lo ve.
:::

## 5. Consumo y coste

Un agente se cobra por uso, y el uso puede crecer sin que nadie lo note. El dato útil no es «gasté tanto este mes», sino **«cada pedido me cuesta tanto»**.

<Flow
  steps={[
    { title: 'Gasto normal', text: 'Todo automático', tone: 'ok' },
    { title: 'Se acerca al tope', text: 'Llega un aviso', tone: 'model' },
    { title: 'Tope alcanzado', text: 'Todo pasa a revisión manual', tone: 'alert' },
  ]}
  caption="Un tope de gasto pone el sistema en modo seguro en vez de seguir gastando."
/>

Los precios los publica cada proveedor y cambian, así que el coste se calcula con una tabla que se actualiza, no con números escritos en el código. Un token es un trozo de texto (más o menos una sílaba); la salida suele costar más que la entrada.

Veinte casos bien elegidos ya detectan muchos problemas. Y se ejecutan solos en la integración continua, para que un cambio que empeora no llegue a publicarse.
:::
